# Calculation methodology

Imported PoB values are exact snapshots when present in the export. They are not silently re-created in TypeScript. Alternate offence scenarios are calculated by the isolated Headless PoB worker; values are unavailable when that authoritative worker is unavailable. No fabricated DPS, effective hit pool, uptime, or defensive state is displayed.

Scenario damage selects PoB `TotalDPS` for hit-based builds, then falls back to `TotalDotDPS` for damage-over-time-only builds such as Righteous Fire, and finally to another positive exported damage channel if needed. The selected channel is stated in the scenario explanation. A zero hit-DPS field is therefore not treated as proof that a DoT build deals zero damage.

Combat scenarios call the pinned Headless PoB version for each explicit configuration, then use a timeline of states. Alternate profiles reset supported conditional inputs before enabling only source-backed conditions detected in the imported build. Unsupported or unverified configured inputs are not silently carried into peak, burst, initial, or mapping results. Reliable minimum-charge sources, such as an ascendancy minimum-charge modifier, remain active in the initial state. The baseline/unconditional profile resets supported condition inputs and custom condition modifiers while retaining build-defining passive, item, gem, and ascendancy modifiers.

Poe.ninja import codes commonly omit `includeInFullDPS` and may retain a low-impact `mainSocketGroup` or skill-part selection. The worker uses PoB's own `mainSocketGroup`/`mainActiveSkill` metadata, then applies only explicit skill-specific peak rules. For Storm Burst of Repulsion, the peak profile selects PoB's documented `Max Duration Explode` part and the four-instance overlap represented by the supplied configured reference export. The imported baseline remains unchanged, and the report must show the peak assumptions; this is not a blanket switch that enables every checkbox.

Sustained DPS is `sum(state DPS * state duration) / encounter duration`; no universal uptime multiplier is applied. The current timeline uses an engine-calculated initial state, a five-second burst assumption, and the configured imported state for the remaining encounter. The burst duration and remaining-state behavior are explicit limitations, not claims of guaranteed uptime.

The worker returns defensive values for each recalculated state, including effective hit pool, physical maximum hit taken, elemental maximum hit taken (the strongest returned fire/cold/lightning maximum hit), chaos maximum hit taken, block, spell block, suppression, and selected recovery fields. The layer analyzer maps the unconditional state to Baseline, the imported export to Typical, and the peak state to Peak. Missing fields remain unavailable; no defensive multiplier is inferred in TypeScript. Every result includes its active conditions, assumptions, confidence, and the pinned engine response.
